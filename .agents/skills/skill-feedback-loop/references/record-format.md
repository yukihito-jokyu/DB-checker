# Feedback Record

1件の起点指摘につき、`.local/skill-feedback/<YYYYMMDD-HHMMSS>-<slug>/feedback.md` を1つ作る。時刻はプロジェクトのローカルタイム、`slug` は指摘対象を表す短いkebab-caseとする。

## 状態

次のいずれかを使う。

- `discussing`: 指摘を議論中。
- `fix-agreed`: 現在の成果物に対する修正を合意済み。
- `artifact-resolved`: 合意した修正と検証が完了。
- `skill-change-proposed`: 仕組みの更新計画を提示済み、承認待ち。
- `approved`: 更新計画が承認済み。
- `applied`: 承認範囲の更新と検証が完了。
- `deferred`: 更新計画を保留または見送り。
- `closed-no-change`: skillなどの更新が不要と判断して完了。

状態を飛ばす場合は理由を記録する。

## 更新規則

- 原文の起点指摘は後から書き換えない。補足は議論と決定へ追記する。
- 現在の結論が変わった場合は古い決定を消さず、新しい日時の項目で変更理由を残す。
- ファイル参照は可能な限り絶対パスのクリック可能なMarkdownリンクにする。
- コマンド出力全文や大きな差分を貼らず、再判断に必要な結果へ要約する。
- 秘密情報、認証情報、個人情報は記録しない。
